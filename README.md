# 小红书创作台

右侧栏里的一条完整小红书图文流水线：

1. **登录**：用本机 Chrome/Edge 打开小红书，实时画面投到右侧栏；支持扫码和手机号验证码。
2. **创作**：拖入 1–9 张图片，自动拼成 1080×1440 的 3:4 封面，标题居中压在拼图上；输入提示词生成配套的标题、正文和标签。
3. **发布**：把拼图（可选原图）上传到创作中心，填好标题、正文和话题，右侧栏显示发布页实时画面，人工核对后再点「确认发布」。

## 打开方式

打开右侧栏（会话右上角的展开按钮）→ 点「+」→ 选择「小红书」卡片。

如果刚安装或刚更新过插件，先刷新一次页面再打开面板，确保加载的是最新前端代码。

## 登录说明

小红书网页版**没有账号密码登录**：登录弹窗只有「扫码」和「手机号 + 验证码」两种方式，创作中心登录页也只有短信登录（已用无痕上下文实测确认）。所以插件目前支持：

- **扫码**（推荐）：点「打开登录页」→「放大二维码」→ 用小红书 App 扫；
- **手机号 + 验证码**：展开「手机号验证码登录」；
- **登录一次后长期有效**：登录态存在 `~/.dsh-xhs/browser-profile`，重启应用、重载插件后仍是登录状态。

如果你需要完全不用手机的操作方式，只能改成「导入浏览器 Cookie」或「复用本机 Chrome 已登录配置」，这需要额外开发。

### 为什么要用有头浏览器 + 直连

- 无头浏览器会被小红书判定为风险环境，直接拦截登录；
- 系统代理（如 Clash）的出口 IP 常被小红书判为高风险，`--no-proxy-server` 可绕过；
- 浏览器窗口默认放在屏幕外（`-2400,0`），你只看右侧栏的实时画面。需要手动操作时点面板里的「显示窗口」，窗口会移到屏幕内并置前；处理完点「隐藏窗口」放回去。

## 发布时的引导浮层

小红书在图片上传后会弹出「图片可以编辑啦」引导层，会挡住底部的「发布」按钮。插件会先尝试自动点「我知道了」；如果没关掉，点「显示窗口」到真实浏览器里手动关闭，再点「确认发布」。发布按钮本身在 `<xhs-publish-btn>` 的 closed shadow root 里，插件已通过 CDP 穿透 shadow DOM 定位真实按钮坐标。

## 套系名称

「创作」步骤提示词下面的输入框已从「语气」改为「套系名称」，例如 `利川红`。生成时会把套系名带进标题和正文，测试输出：

- 标题：`武汉伴手礼选利川红，温柔又高级`
- 正文首段：`湖北特产里，利川红是我最近的心头好🍵`

## 图片上传与发布记录

- 默认勾选「同时上传原图」，封面拼图 + 原图一起传。
- **5 张图的正确流程**（实测平台接口 `images_list` = 5，带 5 个话题标签）：
  1. 先只传第 1 张封面；
  2. 等 5 秒，打开/关闭一次图片编辑；
  3. 剩余图片在图片区**一张一张添加**（每张间隔 2.5 秒），不要一次补多张；
  4. 标题逐字输入、正文分 8 字一段输入，不要整段粘贴；
  5. **不要点「我知道了」等引导层**，填完立刻滚动到底部点发布（直接点 shadow DOM 里的发布按钮）。
- 一次拖入 5 张、或一次补多张、或填完等待/补图，平台都会在发布时裁成 3 张；上面的顺序可以稳定保留 5 张。
- 发布成功后，「发布」步骤底部会记录标题、时间、图片数、状态；点「查看」会在右侧浏览器打开创作中心笔记管理。

## 聊天指令发布（低代码）

低代码用户不需要点侧边栏，直接在聊天框说「把这 4 张图发一个小红书」并附图，Agent 会调用工具：

- `xhs_publish`：发一条。参数 `images`（本地图片路径，1–9 张，第一张作为封面）、`title` / `body` / `tags` 可选；只给 `prompt` 会先生成文案；`account` 默认当前账号；`publish: false` 只填发布页不发布。
- `xhs_batch_publish`：批量。`jobs` / `groups` 会**按账号分组连续执行**（A1、A2、B1、B2），减少换号；同一账号复用登录，新账号首次会在右侧打开登录页等待扫码（默认 180 秒，可传 `loginTimeoutMs`）。
- `xhs_accounts`：列出已保存的账号、昵称、最后使用时间和 profile 目录，用于多账号发布前确认。
- `xhs_login`：登录/切换账号；`wait: false` 只打开登录页，`showWindow: true` 会把浏览器窗口显示出来方便扫码。
- `xhs_group_images`：扫描图片根目录并按账号分组，返回每组账号和图片路径。

多账号：每个账号一个独立 Chrome profile。`default` 用 `~/.dsh-xhs/browser-profile`，其他账号用 `~/.dsh-xhs/accounts/<账号名>`。第一次使用某个账号时右侧会打开登录页，扫码后这个 profile 会记住登录；批量任务切到该账号时会自动复用。

长期记忆：账号表存在 `~/.dsh-xhs/accounts.json`，包含 `lastAccount`、每个账号的昵称、profile 目录和最后使用时间。插件重启后会恢复到上次使用的账号，不用重新扫码；不指定 `account` 时也默认用当前账号，不会每次跳回 `default`。

发布过程中右侧边栏实时显示浏览器画面，用户只需要看，不用操作。返回值逐条包含账号、标题、是否发布、图片数、错误和风控结果。

## 图片分组

图片本身没有账号信息，分组有三种方式：

1. **侧边栏分组（最直观）**：创作步骤顶部「多账号分组」→「+ 添加分组」；每组选账号，把图片拖进该组的虚线框（或点「拖入或点击」选择）；每组可以填自己的提示词；勾选「我已核对每组账号和图片」后点「发布全部分组」，或选时间点「定时发布」。每组只发一篇，图片不会串组。
   - 分组是当前页面的暂存状态，刷新页面会清空；发布/定时前不要刷新。
2. **按文件夹（适合批量和定时）**：根目录下建 `default/`、`账号B/`，图片分别放进去；聊天里说「按 `D:\...\xhs` 的文件夹分组发」，Agent 调 `xhs_group_images` 扫描，每个子文件夹名就是账号名。
3. **按聊天说明**：直接说「前 4 张给 default，后 3 张给账号B」，Agent 按顺序切成 groups。

`xhs_batch_publish` 和 `xhs_schedule_publish` 都支持 `groups` 参数：每个 group = 一个账号 + 这组图 + 可选标题/正文/标签/prompt。一组只会用这个账号发一篇，不会把别的组的图混进来。

没有子文件夹时，`xhs_group_images` 会按文件名里包含的已知账号名分组；文件名都不带账号名时归到 `default`。

## 定时发布

- 聊天里说「明天 10 点发这两篇」并附图，Agent 调用 `xhs_schedule_publish`：
  - `at` 用带时区的 ISO 时间，例如 `2026-10-30T10:00:00+08:00`；或 `delayMinutes`
  - `jobs` 与 `xhs_batch_publish` 相同，支持多账号
- 图片会在创建任务时复制到 `~/.dsh-xhs/schedules/<id>`，任务存在 `~/.dsh-xhs/schedules.json`；插件重载后仍然有效。
- 到点自动执行；**应用需要保持运行**。如果应用当时关闭：
  - 30 分钟内重新打开，会自动补发；
  - 超过 30 分钟标记「已错过」，不会在错误时间发。
- 「发布」步骤新增「定时发布」卡片，显示时间、任务数、账号和状态；待执行的可以取消，已结束的可以删除。
- `xhs_schedules` 工具可以 `list` / `cancel` / `delete` 定时任务。

## 智能敏感词风控预检

- 本地词库扫描标题 / 正文 / 标签，覆盖 5 类：医疗功效、导流交易、违法禁词、绝对化用语、承诺夸大。
- 生成文案后自动检测，显示风险等级（高/中/低/通过）、命中词、所在字段、出现次数和替换建议。
- 支持单条替换和「全部替换」；发布摘要会提示还有几个风险词未处理。
- **词库可自己改**：点风控卡片右上角「词库」查看/编辑，格式一行一个 `等级|类别|词|建议`（建议留空表示删除），保存后立即生效，存放在 `~/.dsh-xhs/risk-words.json`。
- 默认词库在 [risk.js](risk.js)，检测完全本地执行，不联网。

## 拖拽图片

只在右侧面板内拖拽才会被面板接收；面板会阻止事件继续冒泡，中间的对话输入框不会再误收这批图片。把图片拖到面板任意位置都可以（不要求正好落在虚线框里）。

## 已知限制

- 首次启动浏览器需要几秒；首次登录必须人工扫码（或用手机号验证码）。
- 平台改版后选择器可能需要更新，重点是 `fillPublish` / `publishButtonPoint`。
- 聊天工具默认 `publish: true`，会在聊天指令下直接发布真实笔记；只想检查排版时传 `publish: false`（只填发布页）。
- 新账号第一次使用需要在右侧登录页扫码；批量任务会等待登录，超时会在结果里返回未登录错误。
